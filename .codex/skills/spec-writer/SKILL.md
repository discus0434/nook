# Spec Writer

## トリガ

- 挙動変更を伴う中規模以上の機能追加・修正
- 複数ファイル横断の変更
- テスト / docs / CDK まで含めて整理が必要な変更

## 必須フロー

1. 現在の理解を短く要約する
2. 不明点をユーザーに確認する
3. 目的、MVP、ノンゴール、受け入れ条件を合意する
4. 変更対象ファイル、関数、テスト、docs、手動確認項目まで具体化する
5. `specs/TEMPLATE.md` を埋める
6. 実装と docs 更新が終わったら、その spec を削除する前提で進める

## 質問テンプレ

- 何を変えるか、完成状態は何か
- 今回やらないことは何か
- 外部 API / S3 / CDK への影響はあるか
- 自動テストで確認できる範囲と、手動確認が必要な範囲はどこか
- docs 更新箇所はどこか

## 具体化チェックリスト

- 追加 / 更新 / 削除するファイル
- 触るモジュール / クラス / 関数
- 変更する設定ファイルや環境変数
- 自動テストケース
- 手動確認 (`make manual-*`, `make cdk-diff`) の要否
- docs 更新箇所
- spec 削除タイミング
